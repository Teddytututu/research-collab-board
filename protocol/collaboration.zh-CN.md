# 研究协作协议

[English](collaboration.md) · [项目首页](../README.zh-CN.md)

## 目标

用看板连接研究问题、约定实验、可恢复执行和明确的验收决定。每项工作使用稳定的任务编号。

## 分工

| 角色 | 负责事项 | 产出 |
| --- | --- | --- |
| 研究负责人 | 研究问题、假设、对照、解释、范围变更与验收 | 明确判断及其支持证据 |
| 执行者 | 工程设计、代码、实验执行、恢复与交付 | 可复现产物和准确的执行记录 |
| 盲查者 | 按固定判据评估，在可行范围内隐藏预期结果 | 在揭示条件前记录的观察和评分 |
| 部署者 | 账户权限、运行环境、资源限制与付费额度 | 部署设置和明确的运行额度 |

同一参与者可以承担多个角色。任务记录逐项指定负责的人或代理，验收记录写明角色重叠情况。工程实施交由执行者时，研究负责人继续承担研究判断。

## 每项任务都上板

执行前创建任务，探索脚本、核查和后续实验均纳入看板。能够独立恢复的工作建立独立条目，并链接父任务。

每个条目包括：

- 研究问题，以及本任务希望支持的最小判断。
- 研究负责人、执行者和验收人。
- 输入、权限、依赖和具体交付物。
- 开工条件与资源额度。
- 预测、对照、测量方式和验收判据。
- 恢复状态文件和最新产物位置。
- 盲查方案，以及反面结果与零结果的记录位置。

使用[任务模板](../templates/task.md)建立条目。

## 明确开工条件

研究负责人与执行者在开工前确认：

1. 研究问题和交付物具体明确。
2. 输入版本、访问权限、依赖和工作目录已经确定。
3. 预测、对照、指标和决定规则已经写明。
4. 计算、存储、传输、付费额度和停止条件已经约定。
5. 恢复文件、状态更新方式和盲查流程已经确定。

条件涉及用户决定时，任务进入等待阶段，写明具体决定与负责人。其他独立登记的工作继续按各自约定范围推进。

## 固定预测与判据

写明预期变化、比较基线、输入范围和测量方式，同时列出会削弱当前解释的观察。

例如，一个虚构任务比较两种渲染器生成的合成圆形图，预测其中一种在约定运行预算下取得更低的位置误差。实验前明确图形集合、指标、阈值和评估流程。

预测或判据变更时，建立新修订并记录理由。此前观察继续关联当时适用的判据。探索性发现可以形成新的确认性任务。

## 执行与恢复

从能够解决关键疑问的最小运行开始。检查产出后，在部署者额度内扩大实验。

为任务维护恢复文件，例如 `data/recovery/TASK-001.md`，记录：

- 任务编号、责任角色、当前阶段和最近更新时间。
- 输入与版本、配置、命令、环境和工作目录。
- 当前检查点、已完成单元、输出位置和下一条具体动作。
- 实际观察到的进程标识、状态与观察时间。
- 资源用量、剩余额度和适用停止条件。
- 错误、反面结果、决定和恢复动作。

按应用与演示提供的结构，将当前工作和进程摘要写入 `data/attachments/state.json`。开工、检查点、交接、暂停、完成和进程退出时更新状态，并通过受支持的字段关联详细恢复文件。

进程标识用于定位进程，实际输出与检查点用于判断进展。恢复前核对实时进程身份和最新产物。进程结束后记录退出结果，再依据恢复文件确定下一步。

## 开展盲查

检查前固定判据和样本集合。交给盲查者的材料使用中性编号，在可行范围内隐藏方法标签、预期排名和偏好的结论。

盲查者先记录观察，再揭示条件。验收证据保存样本映射和揭示流程。同一参与者兼任执行与检查时，记录该安排，并在可行范围内使用隐藏的样本顺序或条件标签。

后续讨论调整解释时，保留原始观察。

## 保留反面结果

较差结果、零效应、无效运行和失败尝试与正面结果一并记录。每项记录包含设置、观察、可能解释，以及下一项能够区分解释的检查。

分别写明观察结果与解释。结论范围对应实际检查的输入和条件。以检验假设为目标的任务，可以通过完整记录反例完成其研究目标。

## 明确验收

执行者交付产物、恢复状态、测量结果、盲查记录、反面结果和建议结论。使用[验收模板](../templates/acceptance.md)组织交接。

研究负责人对照固定判据，决定接受、返修或建立重新界定的后续任务。记录决定、证据支持的主张、适用范围和验收产物，后续动作登记为看板任务。

使用当前看板的状态标签表达登记、就绪、执行、待验收、接受、返修与暂停。等待事项写明触发条件与决定负责人。

## 分开保存过程与正式材料

过程记录保存命令、时间、诊断、来源锚点、核验细节和恢复指令。正式交付物保存适合目标读者的研究内容。两类材料分别成文，通过任务条目关联。

讨论室用于短消息。行动消息写明结果或决定、任务编号，以及下一步或产物链接。较长技术记录放入任务工作文件。

跨任务的讨论使用[会议模板](../templates/meeting.md)，约定的进展检查使用[巡检模板](../templates/heartbeat.md)。

## 遵循运行额度

部署者配置资源限制与付费额度。每个任务记录适用的计算、并发、存储、传输、服务、币种和支出额度，以及额度变更负责人。

到达停止条件时，保存检查点、更新 `data/attachments/state.json`，记录需要决定的资源或授权事项。该决定形成记录后，恢复依赖相应资源的工作。

## 发布虚构示例

仓库示例保持虚构，包内视觉资源采用原创 SVG 占位图。本地研究数据、自动生成的凭据和部署专用运行记录保存在本地部署工作空间。

按适用许可证发布选定的代码、模板、协议和虚构示例。截图与随包示例遵循相同的发布范围。

## 先讨论，再固定实验

每个候选方向写明机制、预期观察、竞争解释、最省成本的区分实验和停止条件。负责人选择研究方向并固定比较口径，执行者按约定落实测试，再把意外观察交回负责人解释。

## 常见操作问题

接续前核对当前进程身份，统计前固定输入清单与比较方式。盲查标签和模型评分分别保存，标注完成后再揭示映射。模型加载、生成与评分合计占用同一算力额度。保留反面证据和旧状态字节，面向读者交付正式结果，诊断细节进入单独工作记录。

## 多工人协作

主线程负责分派、整合与交付；工人每次领取一个任务，完成并释放后再领取下一项。研究工人持续处理已派实验，网页、学习和打包按各自文件范围推进。

### 领取与心跳

使用 `python scripts/workers.py claim TASK-ID --worker W1 --scope folder/ --allowed-workers 2 --eta "预计完成时间、把握与依据"` 领取。领取工具独占创建任务锁，同时检查工人、任务、并行额度与文件范围。

工人读取返回的 token，每十分钟执行 `python scripts/workers.py heartbeat TASK-ID --token TOKEN`。三十分钟心跳过期后，调度可归档旧锁并重派；新 token 接管写入，历史记录保留。每次开始写入前先校验当前 token。

### 文件范围

领取时声明准确文件或目录。相同路径、父子目录及目录内文件视为交叉范围，由调度安排先后执行。工人负责自己的结果和过程文件。

共享状态用 `board.storage.update_json(data_dir, relative_path, transform)` 按字段更新；看板用 `board.workers.update_board(data_dir, task, status)` 改对应行；交流及任务结果用 `board.workers.append_shared(data_dir, relative_path, text)` 追加。工具跨进程加锁，写前保留原字节。

### 并行与额度

工人数量为额度允许数量、四人上限和本机 CPU 余量三者的最小值。额度估算复用每小时预算与单次成本：先预留未来一天预算的三成，再按单次成本计算人数；比例低于一成或普通调用关闭时，派发数量归零。现有活任务按当前授权完成手头工作。

GPU占用另算物理卡，生成、评分和加载合计。特殊窗口采用用户明确的窗口额度，窗口外采用常规额度；部署的保护卡、共享例外、TTY额度和容量线均按当前项目规则执行。

### 目标与接续

获用户授权的长任务创建独立 goal，写清成果、完成条件、可检查结果与需人工决定的边界。主线程保留实验持续推进目标，研究工人复用服务器控制器、原断点和物理锁。

进程按账号、创建身份和完整命令核对。活进程继续运行；异常退出查原因后修复，临时资源恢复后继续。首次换卡先核对同种子回放；原始样本、种子、模型和评分口径由研究负责人审核。

### 交付

领取后三十分钟内写预计时间、把握和依据；依赖任务采用条件式预计时间。延期更新原因和新时间，完成时记录预计与实际用于校准。

工人在交流板标题标工人编号，正文最多三句。任务结果最多十行，进度、进程身份、断点与长记录集中到 data/attachments。面向用户的讨论室只发结果及必要决定。

使用 `python scripts/workers.py release TASK-ID --token TOKEN --status 待验收` 交回任务；研究审核与最终验收沿现有看板完成。

本仓库默认数据目录为 data/，锁记录在 data/attachments/locks/。领取命令的 --allowed-workers 采用调度按实际额度和CPU余量算出的值，示例中的2是演示许可值。board.workers.quota_capacity提供对应额度计算。共享工具的 relative_path 是 data/ 内的相对路径，state使用 attachments/state.json，文档使用 board.md 与 exchange.md。


持续执行与资源恢复按[执行规则](execution.zh-CN.md)处理。
