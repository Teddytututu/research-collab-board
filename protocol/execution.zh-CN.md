# 在约定范围内持续执行

## 最简执行与真实进度

1. 服务器实验每张物理卡一个进程，按冻结的固定队列循环到空。运行中检查输出存在与大小合理；整批结束统一做一次SHA与逐项核对。资源协调负责按现行用卡规矩数卡，工人直接执行已派任务。
2. 进度只计全部路线终版齐全的组数X/N；看板状态写“X/N · 在做什么 · 约 HH:MM”，60 字以内、用人话；预计时间只认结尾单独的“· 约 HH:MM”。基础阶段、检查项、归档包与许可留在附件。存在可执行任务与合规空卡、且一小时X保持原值时，先把当前流程切回最简实际循环。
3. 交流板用于出结果、需要决定和卡住超过三十分钟这三类消息。每任务每小时至多一条，每条最多三句；当前进度、进程身份、命令与长记录集中到状态文件及附件。
4. 主线程分派两至三名工人，每人一次一个任务，写入范围独立。每位工人复用自己的原生goal，以完整任务的可数成果作为完成条件，例如48/48或300/300加30/30。
5. 冻结计划已经确定的提示、种子、参数和分支直接照做；新增研究决定交研究负责人，其他独立工作持续推进。

| 执行条件 | 动作 |
|---|---|
| 固定循环连续失败两次 | 先向研究负责人说明实际故障与拟改法，再按其回复调整程序。 |
| 统计任务进度 | 从全部路线终版齐全的组数计算X/N，其他数字保存在附件。 |
| 问题持续三十分钟 | 在交流板写一句具体卡点，并同步看板状态。 |
| 第一组完成 | 核对冻结提示、种子、分辨率和参数一次；其余沿同一配置执行，新输出写入新目录，旧结果保留。 |
| 准备加载模型 | 先查看空闲内存；同一服务器同时加载最多两路，加载锁在模型加载返回时释放。 |
| 凌晨使用额外卡位 | 超过常规五卡的分片须预计七点半前自然结束，八点回到现行额度。 |
| 每十五分钟核对账号 | 查看合规卡上的其他账号；按部署的三卡或五卡规则计入生成、评分、加载及物理预留，额外路线在当前分片结束时让位。 |
| 准备修改或清理文件 | 先解析真实路径与junction指向；删除操作取得当次用户确认，数据和他人进程文件按既有边界保留。 |
| goal推进 | 以完整X/N为完成条件；一小时X保持原值且有任务和空卡时，优先恢复实际实验。 |
| 准备交付数字 | 从最终结果文件重新计算结果表，并在核对附件记录文件位置。 |
| 结果盘余量低于20GB | 暂停新分片，向研究负责人说明容量；当前断点与全部已有数据保留。 |

常规恢复沿当前进程和既有断点处理；临时资源恢复后，按同型号合规卡继续。科研方法、付费、账号权限、系统与资源上限变更交相应决定人。GPU0、共享例外、其他用户文件与进程继续按各部署的现行约定保护。

## 轻活、重活与限时

- **轻活直接做**：读论文、看图评分、跑已批准的实验、汇总数字。不建候选包、不做独立复审交接、不给大文件留保护副本；20 条以上互不相干的条目分给多个工人并行。
- **重活走审查**：会被别人使用的代码（看板、守夜人、流转工具）照旧走候选、测试、研究负责人审。
- **工程限时四小时**：从 start 算起，到点就交（附没修完的清单）或 block 写清卡在哪，不再继续修补。实验结果出表之前，不接新的界面和工程活。
- **没人在干就排队**：计数不动且没有进程、没有工人在做的行，用 `task queue` 退回排队。

## 三条红线

- 不向主人要管理员权限，不改操作系统设置。
- 主人的私聊和讨论室消息，醒来先回。
- 状态和讨论室消息写结果和时间，不写内部流程词。

所有看板操作通过 `python scripts/agent.py`，见 [代理命令](../docs/agent-commands.md)。
